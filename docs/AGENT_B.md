# Бриф для агента B — «пользователь, отчёты, фронт»

Скопируйте этот файл целиком в первое сообщение своему агенту (Claude Code и т. п.).

---

Ты работаешь в репозитории `MosPoly_ai_agent`: ИИ-агент проверки трудовых договоров на соответствие ТК РФ (учебный проект). Параллельно с тобой работает **агент A** — он делает конвейер проверки и RAG. Ваши зоны разделены. Прежде чем что-то писать, прочитай:

1. `docs/PLAN.md` — общий план и архитектура;
2. `docs/CONTRACTS.md` — владение кодом, API, роли, зафиксированные интерфейсы, правила Git и миграций;
3. `backend/app/api/v1/schemas.py` — DTO (контракт фронта и бэкенда);
4. ТЗ: `docs/project/ТЗ_ИИ-агент_v5.1.docx` (если файла нет — попроси у пользователя), особенно Ф-10, Ф-13–Ф-18, НФ-05, НФ-06, НФ-09.

Запуск: `cp .env.example .env && docker compose up -d --build` → http://localhost:8080, Swagger — http://localhost:8000/docs. Тесты: `make test` (или `scripts/test.ps1` на Windows).

## Твоя зона

Работай в ветках `b/<тема>`, PR в `main`, маленькими кусками. Не трогай файлы зоны A (см. `docs/CONTRACTS.md`, п. 1). Если нужно изменить контракт (`schemas.py`), делай это только аддитивно, отдельным PR с префиксом `contract:`.

### B1. Авторизация и роли (бэкенд)
- `app/auth/`: JWT access (30 мин) + refresh (14 дней, хранится хешем в `refresh_tokens`, отзыв при logout), argon2 (`app/auth/passwords.py` уже есть).
- Реализовать `POST /auth/token`, `/auth/refresh`, `/auth/logout`, `/users` (GET/POST/PATCH), `/organizations` (GET/POST) в `app/api/v1/auth.py`.
- Заменить тело `get_current_user` в `app/core/security.py` на разбор `Authorization: Bearer`. **Сигнатуры `CurrentUser`, `get_current_user`, `require_role`, `can_read_analysis` не менять.** При `AUTH_DEV_MODE=true` оставить текущее поведение (dev-пользователь), чтобы не ломать работу A.
- Матрица прав — `docs/CONTRACTS.md`, п. 3. org_admin управляет только своей организацией; нельзя повысить себя до service_admin.
- Аудит: `log_event` для входа, выхода и изменений пользователей.
- Тесты: вход, неверный пароль, истёкший токен, refresh, изоляция организаций (пользователь орг. 1 не видит пользователей орг. 2), права ролей.

### B2. Отчёты PDF/DOCX (Ф-14)
- `app/reports/`: построение из `AnalysisResult` (пока — `app.api.v1.fixtures.fixture_result()`, потом — `app.analysis.results.load_analysis_result`, его сделает A).
- Содержимое: шапка (файл, дата, тип документа), сводка по категориям, замечания (критические первыми): номер пункта, цитата из договора, источник (статья, редакция), цитата нормы, пояснение, рекомендация; технические сбои — отдельным разделом; дисклеймер (Ф-18).
- PDF — WeasyPrint из HTML-шаблона (системные библиотеки и шрифты DejaVu уже есть в `backend/Dockerfile`); DOCX — python-docx.
- Эндпоинт `GET /analyses/{id}/report?format=pdf|docx` в `app/api/v1/reports.py`; правильные `Content-Type` и `Content-Disposition` (кириллическое имя — через `filename*=UTF-8''...`).
- Тесты: оба формата генерируются из фикстуры; в PDF есть кириллица.

### B3. Frontend (React + Vite + TS) — `frontend/`
Каркас уже есть (Vite, React 18, nginx-проксирование `/api`). Добавь: React Router, TanStack Query, Mantine (или другой UI-кит), генерацию типов из OpenAPI (`npm run gen:api` уже настроен на `openapi-typescript`).

Экраны:
1. **Вход** (`/login`) — пока бэкенд в dev-режиме, можно сразу пропускать дальше.
2. **Новая проверка** (`/`) — выбор типа документа (`GET /document-types`, неактивные типы показываются, но недоступны), drag-and-drop загрузка, клиентская проверка расширения и размера, серверные ошибки показываются как есть (`error.message`).
3. **Статус** (`/analyses/:id`) — опрос `GET /analyses/{id}`, прогресс, этап; при `failed` — понятное сообщение; при `completed` — переход к отчёту.
4. **Отчёт** (`/analyses/:id/report`) — слева текст договора из `blocks` с подсветкой по `findings[].highlights` (цвет по категории); справа карточки замечаний, отсортированные по категории, с фильтром; клик по карточке прокручивает к фрагменту, и наоборот; блок «Технические сбои»; плашка `is_partial`; кнопки PDF/DOCX; дисклеймер всегда виден (Ф-18).
5. **История** (`/history`) — таблица с датой, файлом, статусом, сводкой по категориям, пагинация, фильтр по статусу.
6. **Нормативная база** (`/regulations`, при `permissions` содержит `regulations:manage`) — источники, версии со статусами, загрузка JSON, активация/архивирование/откат с подтверждением, просмотр фрагментов.
7. **Пользователи** (`/users`, при `users:manage`) — список, создание, смена роли, блокировка.

Требования: весь интерфейс на русском (НФ-05); Chrome и Firefox (НФ-06); access-токен хранить в памяти, refresh — в `localStorage` (учебный компромисс, отметить в README); 401 → попытка refresh → иначе на `/login`.

### B4. Инфраструктура и документация
- `README.md`: быстрый старт на Windows (Docker Desktop, PowerShell) и Linux, как получить **два ключа GigaChat** (LLM и эмбеддинги, разные проекты в личном кабинете), режим mock, частые ошибки (порт занят, CRLF, сертификат НУЦ, нехватка памяти Docker).
- CI: `.github/workflows/ci.yml` — ruff + pytest (сервис postgres `pgvector/pgvector:pg16`, `alembic upgrade head`, `python -m app.cli seed`) + `npm ci && npm run build`.

## Что делает A (не дублируй)
Обработка документа, обезличивание, нормативка в БД, эмбеддинги GigaChat, гибридный поиск, реранкер, LLM-проверка, воркер ARQ, настоящие эндпоинты `/analyses` и `/regulations` (сейчас — заглушки на фикстурах с тем же форматом), оценка качества. Когда A заменит заглушки, фронт должен продолжить работать без изменений: опирайся только на `schemas.py`.
