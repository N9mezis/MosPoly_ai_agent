# Нормативная база

JSON-файлы источников, которые загружаются в БД (`python -m app.cli import-kb`). При первом запуске контейнера `api` загружаются все `*.json` из этой папки, если активной нормативки ещё нет. Файлы `*.example.json` и подпапки не загружаются.

| Файл | Что это |
|---|---|
| `tk_rf_2025-07-31.json` | Полный текст ТК РФ (ред. от 31.07.2025): 525 действующих статей, 1810 частей |
| `source.example.json` | Пример формата |
| `legacy/tk_rf_core_2026-05-15.json` | Ручная выборка из MVP (6 статей, 14 фрагментов), для сравнения |

## Как собрать источник

**Кодекс из PDF** — структурная нарезка «статья → часть»:

```bash
python -m app.cli build-source path/to/TK.pdf                    # весь кодекс
python -m app.cli build-source path/to/TK.pdf --articles 57,70,91 # только выбранные статьи
python -m app.cli import-kb data/regulations/tk_rf_2025-07-31.json
```

Парсер (`backend/app/knowledge/tk_parser.py`):
- рассчитан на PDF-выгрузки справочных систем: абзацы определяются по отступу первой строки, заголовки — по жирному шрифту;
- служебные примечания справочной системы (выделены цветом) и редакционные пометки «(в ред. …)» выбрасываются — в базе остаётся только текст закона;
- нумерация частей учитывает утратившие силу части, поэтому совпадает с официальной: у ст. 68 — части 1 и 3;
- дата редакции берётся из списка изменяющих документов.

**Разъяснения, письма, обзоры практики** — свободная нарезка по абзацам (~1000 символов с перекрытием):

```bash
python -m app.cli build-source rostrud/*.pdf --mode text --source-id rostrud --title "Разъяснения Роструда"
```

У таких фрагментов не заполняется `article`: основанием замечания остаётся норма кодекса, а разъяснения дают контекст модели.

## Правила

- Текст норм — только из официального источника или его точной копии, без пересказа. Комментарии справочных систем не загружаются.
- Новая редакция — новый файл и новая версия в базе. Старая версия уходит в архив, откат — её повторная активация (`POST /api/v1/regulations/versions/{id}/activate`).
- `source_id` для ТК — `tk_rf`; профиль проверки трудового договора смотрит на этот источник.
